# LightMeterApp

> 이 프로젝트의 `.md` 문서는 한국어로 작성합니다.

내장 노출계가 없는 필름카메라와 수동 카메라의 촬영 설정을 돕는 Android 앱입니다. 상단의 실시간 카메라 프리뷰를 보면서 하단의 조리개, 셔터스피드, ISO를 세로 스와이프로 조절합니다. 직접 설치용 APK로 배포합니다.

현재 구현의 중심은 **수동 설정에 따른 프리뷰 노출 시뮬레이션**입니다. 실제 장면의 밝기를 측정해 보정된 EV100을 제공하는 측광 기능은 아직 구현되지 않았습니다.

## 문서 기준과 버전

현재 개발 소스는 Color/B/W 프리뷰, 초기 AE 기반 자동 시작 설정·필름 ISO 저장, AUTO 일회성 재측광과 A/S 우선순위 선택을 포함합니다. 이 기능들은 아직 APK로 배포하지 않았으며, 배포 이력과 개발 변경은 구분합니다.

| 항목 | 현재 상태 |
| --- | --- |
| `main` 앱 버전 | `versionName = 1.0.0`, `versionCode = 1000` |
| 최신 배포 버전 | [GitHub Release `v1.0.2`](https://github.com/BattleMarine/LightMeterApp/releases/tag/v1.0.2) (APK 첨부) |
| `v1.0.1` 태그의 코드 | `a6cdda2`, 버전 `1.0.1` / `1001` |

| 현재 개발 소스 시작 정책 | 저장 우선순위(최초 A)와 필름 ISO(첫 설치 100) 사용. A는 `f/4.0` 유지·셔터 선택, S는 준비 카드 셔터 `1/60s` 유지·조리개 선택. 준비값을 물리 셔터로 강제하지 않음 |

현재 `main`에는 물리 노출 보정 경로 정리, 프리뷰 셔터 지연 제한, 빌드 도구 업데이트가 커밋되어 있습니다. `release-1.0.2`에는 별도로 프리뷰 보정 예약 수정과 release 서명 설정이 있으며, 이 두 변경은 현재 `main`에 포함되어 있지 않습니다. 다음 배포 전에는 시작값과 버전 번호를 확인해야 합니다.

## 현재 기능

### 라이브뷰와 카메라

- 앱 실행 시 카메라 권한을 확인하고, 없으면 런타임 권한을 요청합니다.
- CameraX `PreviewView`를 Activity 생명주기에 연결합니다. 후면 카메라를 우선 사용하고, 없으면 전면 카메라를 선택합니다. 사용자가 카메라를 선택하는 UI는 없습니다.
- Camera2 interop으로 실제 조리개, 노출 시간, ISO 및 AE/AF 상태 메타데이터를 읽습니다.
- 초기에는 AE 프리뷰로 시작하고, 아래 자동 시작 설정을 거친 뒤 수동 센서 제어 지원 기기에서는 AE를 끄고 노출 시간과 ISO를 요청합니다. 조리개는 기기가 제공하는 값 중 가까운 값을 선택합니다.
- 수동 제어 경로에서는 AF를 끄고 무한대 초점을 요청합니다. 모든 거리에 초점이 맞는 팬포커스를 보장하지 않으며, 별도 심도·배경 흐림 효과는 없습니다.
- 수동 센서 제어 미지원 기기에서는 자동 노출을 유지하며 지원 범위 안의 노출 보정값을 요청하고, 메타데이터를 이용한 프리뷰 보정을 시도합니다.
- 사진 촬영·저장 기능은 없으며, 프리뷰 용도로 사용합니다.

### 초기 자동 설정과 필름 ISO 저장

- 최초 우선순위는 A이며 이후에는 저장된 A/S를 사용합니다. 새 실행에서 A는 `f/4.0`, S는 준비 카드 셔터 `1/60s`를 기준으로 초기 AE 설정을 수행합니다. 카드 ISO는 필름 감도로 취급해 마지막 사용자 선택값을 저장·복원하며 첫 설치는 100입니다. 물리 ISO와 별도의 마지막 셔터는 영속 저장하지 않습니다. ISO 저장값이 현재 목록에 없으면 그 값을 포함하는 스톱 프리셋을 선택해 정확히 복원하고, 유효하지 않은 저장값은 100으로 되돌립니다.
- 최초 카메라 연결 후 AE ON·노출 보정 0·플래시 OFF를 요청합니다. 요청 적용 완료와 이후 요청에 대응하는 캡처 결과를 확인한 뒤, 실제 조리개·셔터·ISO가 모두 유효하고 AE가 `CONVERGED`이면 우선순위에 따른 등가 후보를 선택합니다. 요청값을 실제 센서 적용값으로 대신하지 않습니다.
- A는 필름 ISO·조리개를 유지해 셔터를, S는 필름 ISO·셔터를 유지해 조리개를 고릅니다. 현재 UI 프리셋 중 로그 노출 오차가 가장 작은 후보를 요청하고, 실제 적용 결과 확인 뒤 해당 카드만 갱신합니다. 물리 보정은 기존 등가 ISO·셔터 계산을 사용합니다. 이는 AE 추천 설정의 환산이며 보정된 절대 장면 측광값이 아닙니다.
- 자동 조정할 축의 UI 범위가 부족하면 경계값을 선택하고 `설정 범위 초과 · 너무 밝음/너무 어두움`을 표시합니다. 카드 ISO를 임의로 바꾸지 않습니다. 이후 카드 수동 조작은 이 초기 안내를 해제합니다.
- AE 대기는 최대 4초입니다. 수렴하지 않거나 AE 상태가 null·SEARCHING·FLASH_REQUIRED 등으로 남아도 유효한 메타데이터가 있으면 마지막 결과로 환산하고 `자동 설정 확인 필요`를 표시합니다. 유효한 결과가 없으면 카드의 임시 셔터를 강제하지 않고 `자동 설정 실패 · 자동 프리뷰`로 남습니다.
- 수동 전환과 일반 노출 요청은 요청 적용 완료 후 새 요청에 대응하는 유효 결과를 최대 2초 기다립니다. 실패·시간 초과 시 가상 보정을 끈 자동 프리뷰로 복귀를 요청합니다. 그 복귀도 확인되지 않으면 연결 확인 안내를 표시합니다. 드라이버가 요청을 거부하거나 메타데이터를 누락하는 기기에서 복귀나 밝기를 보장하지 않습니다.
- 수동 센서 제어 미지원 기기는 AE를 유지하며 기존과 같은 범위의 노출 보정과 메타데이터 기반 시뮬레이션을 사용합니다. 결과를 확인할 수 없는 경우에는 가상 보정을 억제한 자동 프리뷰를 유지합니다.
- 준비 중 조리개·셔터·ISO 또는 스톱 프리셋을 직접 조작하면 초기 자동 설정을 취소하고 사용자의 선택을 우선합니다. 늦은 AE 결과와 이전 요청 완료 콜백은 카드 값을 덮어쓰지 않습니다. Color/B/W 전환은 초기 측정을 취소하지 않습니다.
- 앱 중단 시 대기·예약을 취소하고 카메라를 해제합니다. 완료 전 중단했다면 복귀 후 초기 측정을 다시 시작하고, 완료했거나 직접 조작했다면 현재 카드를 유지합니다. 권한 거부 시 안내를 표시하고, 설정에서 권한을 허용한 후 앱으로 복귀하면 카메라 연결을 다시 시도합니다.
- AE 중과 실패 자동 프리뷰에서는 기존 가상 보정을 제거합니다. 일반 수동→수동 전환에서는 마지막 화면 보정을 유지하고 예약·애니메이션만 무효화한 뒤 새 요청과 대응하는 실제 결과로 갱신합니다. 화면 깜박임을 줄이기 위한 처리이며 프리뷰 프레임과의 완전한 동기화를 보장하지 않습니다.
- release에도 준비·실패·프리셋 범위 초과 등 필요한 짧은 상태 안내는 표시합니다. 개발용 EV·센서 수치 표시는 여전히 debug 전용입니다.

요청 적용 확인은 [Camera2CameraControl의 완료 Future](https://developer.android.com/reference/androidx/camera/camera2/interop/Camera2CameraControl#setCaptureRequestOptions(androidx.camera.camera2.interop.CaptureRequestOptions))와 CameraX 1.4.2 라이브러리 소스를 대조했습니다. [CaptureCallback의 요청과 실제 결과](https://developer.android.com/reference/android/hardware/camera2/CameraCaptureSession.CaptureCallback#onCaptureCompleted(android.hardware.camera2.CameraCaptureSession,android.hardware.camera2.CaptureRequest,android.hardware.camera2.TotalCaptureResult)), [AE 상태 메타데이터](https://developer.android.com/reference/android/hardware/camera2/CaptureResult#CONTROL_AE_STATE)를 구분해 검사하며, null 상태와 누락 메타데이터를 성공으로 간주하지 않습니다.

### A/S 우선순위

- 조작부 첫 줄의 A/S 선택부에서 A는 조리개 우선, S는 셔터 우선입니다. 선택 상태를 색과 라디오 선택 상태로 표시하며 접근성 설명에 유지할 값과 자동 조정할 항목을 제공합니다. 기존 제목 자리를 사용하므로 행을 추가하거나 조작부 높이를 늘리지 않습니다.
- 선택만 바꿀 때는 카드 값과 물리 노출 요청을 변경하지 않습니다. 다음 AUTO에 선택한 우선순위를 한 번 적용합니다. A는 현재 조리개·ISO를 유지하고 셔터만, S는 현재 셔터·ISO를 유지하고 조리개만 바꿉니다.
- 마지막 우선순위를 저장하고 다음 새 실행의 초기 AE에도 적용합니다. 기본값은 A입니다. S의 새 실행 기준 셔터는 `1/60s`이며 별도 마지막 셔터 영속 저장을 추가하지 않았습니다. Activity 재생성에서는 현재 카드와 모드를 함께 복원합니다.
- 초기 AE 또는 AUTO의 측정·적용 중 A/S를 바꾸면 진행 중 선택을 취소하고 기존 카드를 유지합니다. AUTO는 이전 프리뷰 요청을 복원하고, 초기 설정은 이전에 확정한 수동 프리뷰가 없으므로 가상 보정을 끈 AE 프리뷰로 돌아갑니다. 새 우선순위로 측정을 자동 재실행하지 않습니다. 이미 복원 중이라면 모드만 저장하고 진행 중 복원을 이어갑니다.
- S의 등가 조리개는 `N = sqrt(N_physical² × t_card × ISO_card / (t_physical × ISO_physical))`에 해당하는 로그 공간에서 선택합니다. 조리개값이 커질수록 빛이 줄어드는 방향을 반영해, 최소 조리개값보다 더 열어야 하면 부족·최대 조리개값보다 더 조여야 하면 과다로 안내합니다. A는 기존 시간의 로그 오차 계산을 유지합니다.

### AUTO 일회성 재측광

- 조작부 제목 옆의 `AUTO`는 한 번 눌러 다시 측광하는 푸시버튼입니다. 지속 자동 노출 토글이 아니며, 완료 후 장면이 바뀌어도 카드 값을 계속 추적·변경하지 않습니다. 미지원 기기의 물리 AE 프리뷰는 기존처럼 유지될 수 있습니다.
- 현재 우선순위를 사용합니다. A는 현재 카드 조리개·필름 ISO로 셔터만 선택하고, S는 현재 카드 셔터·필름 ISO로 조리개만 선택합니다. AUTO에서 조리개를 f/4.0이나 셔터를 1/60s로 초기화하지 않습니다. 새 수동 요청(미지원 기기는 AE 보정 요청)에 대응하는 실제 결과까지 확인한 뒤 선택한 축의 카드만 갱신합니다. 적용 확인 전에는 기존 카드 값이 유지됩니다.
- 카메라 권한이 없거나 연결 준비 전, 초기 AE 측정 중, 노출 요청 적용 중, 재측광·복원 중에는 버튼을 비활성화합니다. 진행 상태를 표시하며 연속 클릭으로 중복 요청을 만들지 않습니다.
- 재측광 AE 대기는 최대 4초입니다. 초기 시작과 달리 미수렴·null AE 상태의 결과를 타임아웃 시 채택하지 않습니다. 수렴 실패·메타데이터 누락·요청 실패는 카드 값을 유지하고 이전 프리뷰 요청을 복원하는 경로로 처리합니다.
- 이전 요청 옵션과 필름 카드 값을 기준으로 물리·가상 프리뷰 복원을 시도하고, 실제 복원 결과를 확인한 뒤 실패 안내를 유지합니다. 요청 적용·복원은 각각 최대 2초 기다립니다. 복원 자체가 실패하면 `이전 설정 복원 실패 · 자동 프리뷰`로 전환하며 카드 값은 그대로 둡니다. 하드웨어 요청 수용이나 이전 표시 프레임의 정확한 복원은 보장하지 않습니다.
- 측정·적용·복원 중 카드나 스톱 프리셋을 직접 조작하면 재측광을 취소하고 새 사용자 선택을 우선합니다. 이전 AE 결과나 늦은 수동 요청 완료가 선택값을 덮어쓰지 않습니다. Color/B/W 전환은 재측광을 취소하지 않습니다.
- 앱 중단 시 재측광은 취소하고 대기·예약·카메라를 해제합니다. 복귀하면 이전 프리뷰를 복원하며 측정을 자동 반복하지 않습니다. Activity 재생성 시에도 기존 카드 값을 복원해 프리뷰를 다시 계산·요청합니다. 이전 물리 요청 객체는 저장 상태로 직렬화하지 않습니다.
- AE 중에는 가상 보정을 제거하고 복원·적용 결과 확인 뒤 실제 센서값으로 다시 계산합니다. 일반 수동 스와이프의 마지막 보정 유지 정책은 바꾸지 않습니다. 자동 ISO·지속 AUTO·P/M·프리뷰 터치 재측광·디자인 개편은 포함하지 않습니다.

### Color / B/W 프리뷰

- 조작부 상단의 스위치로 실제 프리뷰 영상의 Color/B/W 표시를 전환합니다. 꺼짐은 `Color`, 켜짐은 `B/W`이며 처음 설치했을 때 기본값은 Color입니다.
- 마지막 선택은 앱 전용 `SharedPreferences`에 저장하고, 재실행 및 Activity 재생성 시 프리뷰 생성 전에 복원합니다. 앱 데이터 삭제 시 기본값으로 돌아갑니다.
- A/S 선택부와 AUTO 버튼은 한 줄로 두고 설명 문구를 표시하지 않습니다. 스톱 선택과 모드 스위치는 그 아래에 배치합니다. 화면 너비가 360dp 미만이거나 글꼴 배율이 1.3을 넘으면 두 옵션을 세로로 배치합니다. A/S 행과 버튼·옵션의 조작 영역 높이는 최소 48dp이며, AUTO 라벨은 진행 중에도 바꾸지 않습니다.
- 흑백은 채도 0의 `ColorMatrixColorFilter`를 영상 `PreviewView`의 하드웨어 레이어에 적용합니다. Color로 돌아오면 필터와 추가 레이어를 해제합니다. 프레임을 CPU로 읽거나 비트맵으로 복사하지 않으며, 전환 시 카메라 재바인딩이나 물리 노출 요청을 하지 않습니다.
- `PreviewView.ImplementationMode.COMPATIBLE`을 유지합니다. [공식 PreviewView 문서](https://developer.android.com/reference/androidx/camera/view/PreviewView#setImplementationMode(androidx.camera.view.PreviewView.ImplementationMode))와 CameraX 1.4.2 소스의 `shouldUseTextureView()` 및 `TextureViewImplementation.initializePreview()`에서 이 모드가 `TextureView`를 자식으로 배치함을 확인했습니다. [TextureView](https://developer.android.com/reference/android/view/TextureView)는 별도 창 대신 일반 View 계층에 합성되며, [하드웨어 레이어의 Paint 필터](https://developer.android.com/topic/performance/views/hardware-accel-views#view-layers)로 흑백 효과를 줄 수 있습니다. 사용 API는 최소 SDK 26에서 지원됩니다. `SurfaceView`를 사용하는 PERFORMANCE 모드로 바꾸면 이 방식을 그대로 적용할 수 없습니다.
- 필터 대상은 영상 View뿐입니다. 형제 View인 흰색·검정색 밝기 보정 오버레이와 개발 텍스트, 조작부는 그대로 합성합니다. 모드 전환은 조리개·셔터·ISO 카드 선택값, 물리 제어 및 메타데이터 계산에 영향을 주지 않습니다.
- 특정 흑백 필름의 색 반응·입자·대비를 재현하지 않습니다. 하드웨어 합성 결과, 전환 시 연속 영상 갱신, 성능 및 작은 화면 배치는 실기기에서 확인해야 합니다.

### 조작부

- 왼쪽 조리개, 중앙 셔터스피드, 오른쪽 ISO의 세로 카드 3개를 배치합니다.
- 유효한 스와이프 한 번에 눈금 한 칸만 이동합니다. 길게 밀어도 여러 칸을 건너뛰지 않으며, 28dp 이하의 움직임은 값 변경으로 처리하지 않습니다.
- 선택값은 중앙에 한 줄로 표시하고, 변경 시 숫자가 위아래로 이동하는 애니메이션을 사용합니다. 다이얼 회전 애니메이션은 없습니다.
- 드롭다운에서 `1stop`, `1/2stop`, `1/3stop` 프리셋을 선택합니다. 전환 시 각 항목을 새 목록에서 수치상 가장 가까운 값으로 맞춥니다.
- 모든 단계의 전체 범위는 조리개 `f/1.0 ~ f/32`, 셔터 `1/2s ~ 1/2000s`, ISO `25 ~ 25600`입니다. 단계마다 중간 눈금이 달라집니다.
- **현재 불일치:** `halfStopPreset`의 셔터 목록은 `thirdStopPreset`과 같습니다. `1/2stop` 셔터 눈금은 별도 수정·검증이 필요합니다.
- 수동 카드 조작에서 다른 카드 값은 자동으로 바뀌지 않습니다. 초기 자동 설정과 AUTO 재측광에서만 A는 셔터, S는 조리개를 선택하며 필름 ISO를 유지합니다. 프리뷰를 맞추기 위한 물리 카메라 설정 변경과 구분합니다.

### 화면 정책

- 세로 화면을 사용하며, 상단 헤더와 라이브뷰 아래에 조작부를 배치합니다.
- 실행 및 복귀 시 상태바와 내비게이션바를 숨깁니다. 시스템 제스처로 일시 표시할 수 있습니다.
- Android 9 이상에서 디스플레이 컷아웃을 사용하지 않도록 요청합니다. OS·기기별 실제 배치는 실기기로 확인해야 합니다.
- 조작부 높이는 화면 높이에 따라 `300 / 316 / 332 / 344 / 356dp` 중 하나를 선택합니다. 비율 기반 높이가 아니며, 라이브뷰가 나머지 공간을 차지합니다.
- debug 빌드는 프리뷰 위 상태·노출 텍스트와 지표를 표시합니다. release 빌드는 이 개발용 표시를 숨기며, 초기 설정 진행·실패·범위 초과 등 사용자 안내만 유지합니다. 이는 브랜치명이 아닌 `BuildConfig.DEBUG`에 따른 동작입니다.

## 노출 계산과 프리뷰 보정

### 용어와 수식

조리개값을 `N`, 노출 시간을 초 단위 `t`, 감도를 `S`로 두면 다음과 같습니다.

```text
설정 EV = log2(N² / t)
ISO 100 기준 설정 환산값 E = log2(N² / t) - log2(S / 100)
```

`E`는 설정 조합을 비교하는 값입니다. 장면을 측광해 얻은 EV100과 자동으로 같아지는 것은 아닙니다. 같은 장면에서 `N`이 커지거나 `t`가 짧아지면 노출은 줄어들며 `E`는 커집니다. ISO를 두 배로 올리면 `E`는 1 작아지고 영상의 밝기는 증가하는 방향입니다.

이상적인 한 스톱 변화는 조리개값의 `sqrt(2)`배, 시간 또는 ISO의 2배 변화입니다. 현재 코드는 표시용으로 반올림한 프리셋 수치를 그대로 계산에 쓰므로, 인접 눈금의 계산 차이가 정확히 1, 1/2, 1/3EV가 아닐 수 있습니다.

코드의 `calculateSettingEv100()`은 이름과 달리 ISO 보정 전 `log2(N² / t)`를 계산합니다. `exposureFactorForSetting()`에서 ISO 보정을 뺍니다.

### 장면 측광의 현재 한계

`sceneEv100`은 **16.0으로 고정**되어 있습니다. 초기 AE 추천 설정을 필름 ISO로 환산하는 단계는 있지만, 이미지 밝기 분석이나 보정된 절대 장면 EV 측광은 없습니다. 수동 노출 상태의 조리개·시간·ISO 메타데이터만으로는 실제 장면 밝기를 알 수 없습니다.

debug 화면의 `Physical EV100`, `Virtual EV100`은 현재 다음 내부 계산값입니다.

```text
내부 밝기 지표 B = 2 × sceneEv100 - E
프리뷰 보정 Δ = B_virtual - B_physical = E_physical - E_virtual
보정 배율 = 2^Δ
```

따라서 절대 표시값은 보정된 측광 결과로 해석하면 안 됩니다. 물리 설정과 가상 설정의 차이에서는 고정 장면값이 상쇄됩니다. `Δ > 0`이면 프리뷰를 밝게, `Δ < 0`이면 어둡게 보정하는 방향입니다.

### 물리 제어 우선순위

1. 사용자가 선택한 가상 조리개·셔터·ISO 조합을 목표로 삼습니다.
2. 기기의 실제 조리개값을 고려하고, 프리뷰 허용 범위 안에서 요청한 셔터를 우선 유지하며 등가 ISO를 계산합니다.
3. 필요한 ISO가 기기의 감도 범위를 벗어나면 ISO를 경계값으로 제한하고 등가 셔터 시간을 직접 계산합니다. 최종 셔터를 프리뷰 범위로 제한한 뒤 ISO를 다시 계산·제한합니다.
4. 캡처 메타데이터가 도착하면 실제 설정과 목표 설정의 차이를 계산해 프리뷰 오버레이 갱신을 예약합니다.

현재 `resolvePhysicalExposureTarget()`은 UI 눈금에 맞춰 물리값을 선택하지 않고 등가값을 직접 계산합니다. ISO는 `SENSOR_INFO_SENSITIVITY_RANGE`로 제한하며, 범위 정보가 없으면 UI 프리셋의 최솟값·최댓값을 사용합니다.

물리 셔터는 `1/1,000,000초 ~ 1/10초`로 제한합니다. 사용자가 카드에서 선택한 가상 셔터는 유지되며, 물리 프리뷰에서 부족한 노출은 ISO와 오버레이로 보정합니다. debug 메타데이터 표시에는 해당 조건에서 `Preview shutter capped at 1/10s`가 추가됩니다. 이 제한은 프리뷰 지연을 줄이기 위한 정책이며 일정 FPS를 보장하지 않습니다.

기기의 `SENSOR_INFO_EXPOSURE_TIME_RANGE`는 읽지만 현재 셔터 제한 함수에서 사용하지 않습니다. 따라서 실제 하드웨어 범위 내 요청이 항상 보장되는 것은 아닙니다. 드라이버가 요청을 제한하거나 거부할 수 있으므로 요청값과 실제 메타데이터를 구분해야 합니다.

### 가상 보정의 범위

- 현재 `main`은 `alpha = 1 - 2^(-abs(Δ))`로 오버레이 강도를 계산합니다. 양수는 흰색, 음수는 검정색이며 별도 EV 제한이나 `0.72`·`0.88` 알파 상한은 없습니다. 차이가 커지면 알파는 1에 가까워집니다.
- 기존 `v1.0.1`은 스톱 차이의 절댓값에 비례하는 알파를 사용하고 최대 `0.65`로 제한합니다. 기존에도 검정 오버레이 분기가 있었으며, 현재 변경은 감광 분기 추가가 아닌 보정 강도 계산 변경입니다.
- 초기 AE와 요청 재측광 AE에서는 보정을 억제합니다. 일반 전환에서는 이전에 적용한 보정을 유지하되, 새 요청 Future 완료·요청 옵션·결과 AE 모드·프레임 번호를 확인한 이후의 실제 조리개·시간·ISO로 잔여 보정을 계산합니다. 센서가 요청을 제한한 경우도 결과값을 사용합니다.
- 이전의 프레임마다 재예약하던 90ms 대기와 140ms 알파 애니메이션은 제거했습니다. 현재는 최신 보정값을 한 번 예약한 16ms 작업에서 합치고 알파를 직접 갱신해 예약 밀림과 이전 애니메이션 잔류를 줄입니다. 16ms는 UI 작업 병합 간격이며 일정 FPS나 표시 프레임 동기화를 의미하지 않습니다. 급격한 광량 변화와 큰 잔여 보정에서의 밝기 점프는 실기기 확인이 필요합니다.
- 오버레이는 화면 합성에 의한 근사입니다. 선형 광량 기반 영상 처리, 포화된 하이라이트 복원, 필름의 색·계조·심도 재현을 제공하지 않습니다.

## 승인된 단계별 구현 계획

2026-10-19 합의 중 초기 자동 설정·필름 ISO 저장, AUTO 일회성 요청 재측광과 A/S 우선순위 선택을 구현했습니다. 최초는 A이며 이후 저장 우선순위를 사용합니다. 디자인 개편·자동 ISO·지속 AUTO·P/M은 미구현입니다. AE 추천 환산을 절대 장면 측광과 구분하는 원칙은 계속 유지합니다.

### 필름 감도와 자동 설정 정책

- 사용자 카드의 ISO는 필름 감도로 취급합니다. 마지막 사용값을 저장·복원하고, 첫 설치에서만 ISO 100을 기본값으로 사용합니다.
- 자동 시작 설정과 사용자가 요청한 재측광에서는 카드 ISO를 유지합니다. 사용자는 ISO 카드를 직접 변경할 수 있으며, 이 정책은 ISO 조작을 잠그는 기능이 아닙니다.
- 휴대폰의 물리 ISO는 별개의 값입니다. 필름 ISO를 유지하더라도 프리뷰 노출 보상을 위해 물리 ISO는 변경할 수 있습니다.
- 자동 설정으로 조정할 사용자 카드 값은 다음 우선순위 정책을 따릅니다. 여기서 유지하는 값은 사용자 카드 값이며, 물리 카메라 제어 우선순위와 구분합니다.

| 자동 설정 우선순위 | 유지할 사용자 카드 값 | 자동으로 조정할 사용자 카드 값 |
| --- | --- | --- |
| 조리개 우선 | 조리개, 필름 ISO | 셔터만 조정 |
| 셔터 우선 | 셔터, 필름 ISO | 조리개만 조정 |

- 필요한 조합이 UI 프리셋 범위를 벗어나면 필름 ISO를 임의로 바꾸지 않고 노출 과다·부족을 표시합니다. 휴대폰의 물리 지원 범위와 UI 프리셋 범위는 별도로 다룹니다.
- 이후 설정에 `자동 노출 시 ISO 변경 허용`을 추가하는 방안은 확장 후보로 남깁니다. 값 잠금 기능은 보류합니다.

### 단계별 구현 순서

1. **자동 시작 설정 (구현, 실기기 검증 대기):** 저장된 A/S와 필름 ISO를 사용해 A는 f/4.0 기준 셔터를, S는 1/60s 기준 조리개를 선택합니다. 실제 요청 결과 확인 뒤 반영하며, 대기·실패·사용자 취소 정책은 위의 현재 기능을 따릅니다.
2. **요청 재측광 (구현, 실기기 검증 대기):** AUTO 푸시버튼으로 현재 우선순위와 유지할 카드·필름 ISO를 사용한 일회성 재측광을 수행합니다. 미수렴 타임아웃에서는 기존 카드를 보존하고 이전 프리뷰 복원을 시도합니다.
3. **우선순위 선택 (구현, 기기 검증 대기):** A/S 선택, 마지막 모드 저장과 양쪽 자동 선택 축 계산을 구현했습니다. 선택만으로 노출 요청을 바꾸지 않으며, 진행 중 모드 변경은 취소·복원으로 처리합니다.
4. **디자인·애니메이션 개편:** 앞 단계의 동작을 바탕으로 화면 디자인과 전환 애니메이션을 개편합니다. 구체적인 화면과 효과는 별도 설계 대상으로 둡니다.

AE 메타데이터로 얻는 결과는 휴대폰 AE가 추천한 설정을 필름 ISO에 맞춰 환산하는 데 사용합니다. 이를 보정된 절대 장면 측광값으로 취급하거나, 이 계획만으로 장면 EV 측광·캘리브레이션이 완료된 것으로 설명하지 않습니다.

### 미정 사항과 설계 검토 항목

- 시작 기본은 최초 A의 f/4.0, 저장 S의 준비 셔터 1/60s로 확정했습니다. A/S 선택 UI도 구현했으며, 별도 셔터 영속 저장이나 추가 모드 확장은 이번 범위에 포함하지 않았습니다.
- 요청 재측광은 일회성 AUTO 푸시버튼으로 확정했습니다. 지속 AUTO와 프리뷰 터치 제스처는 구현하지 않습니다.
- 초기 설정의 AE 4초·요청 2초 대기와 요청 검증을 재측광에 재사용했습니다. 재측광은 실패 시 기존 설정 복원을 우선한다는 차이가 있습니다. 실제 기기별 수렴 지연·null 메타데이터·권한 전환·미지원 기기 동작은 검증 과제로 남깁니다.

## 실행과 검증

1. Android Studio에서 저장소 루트 폴더를 엽니다.
2. SDK Manager에서 Android SDK 35를 준비하고 Gradle Sync를 실행합니다. 저장소의 데몬 JVM 기준은 JDK 21이며, Java/Kotlin 컴파일 타깃 17과 구분합니다. JVM 도구 체인 다운로드에 필요한 네트워크 또는 로컬 JDK 환경을 확인합니다.
3. 실행 구성에서 `app`과 기기 또는 에뮬레이터를 선택하고 Run을 실행합니다.
4. 카메라 권한을 허용합니다. 실제 노출 반영·초점·컷아웃·기기 한계는 실기기로 확인합니다.

Windows PowerShell에서 debug APK 빌드:

```powershell
.\gradlew.bat assembleDebug
```

결과: `app/build/outputs/apk/debug/app-debug.apk`

2026-10-17 검증에서는 `assembleDebug "-Pkotlin.compiler.execution.strategy=in-process"`가 AGP 9.4.1·Gradle 9.6.0에서 성공했습니다. 기본 실행은 샌드박스의 SDK·Kotlin 데몬 파일 접근 제한으로 실패해, 필요한 파일 접근을 허용하고 Kotlin 컴파일을 같은 프로세스에서 실행했습니다. 저장소의 빌드 옵션은 이 우회를 위해 수정하지 않았습니다.

같은 옵션의 `lintDebug`는 기존 Camera2 interop opt-in 오류 24건과 경고 39건을 보고하며 실패했습니다. `c9181fd` 소스를 `build/` 아래에 별도로 복사한 기준 검사(AGP 9.3.1·Gradle 9.5.0)에서도 같은 오류·경고 수가 나왔고, `MainActivity.kt` 진단 43건은 최종 검사와 소스 지문이 모두 일치했습니다. B/W 변경에서 추가된 lint 진단이나 무관한 코드 자동수정은 없습니다. 실기기 영상 검증을 통과했다는 의미는 아닙니다.

2026-10-19에는 사용자가 에뮬레이터에서 B/W 기능을 테스트해 정상 동작을 확인했다고 보고했습니다. 에이전트가 직접 실행한 검증과 구분해 기록하며, 실기기는 디버거 연결 문제로 확인하지 못했습니다.

같은 날 초기 AE 자동 시작·ISO 저장 구현에서 `assembleDebug testDebugUnitTest lintDebug "-Pkotlin.compiler.execution.strategy=in-process"`가 성공했고 JVM 테스트 13개가 통과했습니다. Camera2 interop 사용 범위를 명시적으로 opt-in해 위의 과거 lint 오류는 해소했으며 기존 경고 39건은 남아 있습니다. 이 결과는 실제 카메라의 AE 수렴·밝기 전환·권한 화면을 실행해 검증한 결과가 아닙니다. 앞의 사용자 B/W 확인을 이번 초기 AE 기능 검증으로 대신하지 않습니다.

이후 AUTO 일회성 재측광 구현에서도 같은 빌드·테스트·lint 명령이 성공했고, 테스트는 총 20개로 늘었습니다. 현재 조리개·필름 ISO 유지, 적용 확인 전 카드 보존, 미수렴 실패, 복원·사용자 취소·중단, 중복 클릭과 늦은 콜백 차단을 추가 검증했습니다. 기존 lint 경고 39건은 유지됩니다. 개발 세션이 이 검증을 수행한 당시에는 연결된 기기가 없어 AUTO 버튼의 실제 화면과 카메라 재측광은 실행 검증하지 못했습니다.

그 뒤 2026-10-19 총괄 세션이 연결된 `emulator-5554`에 최신 debug APK를 설치·실행해 정상 경로를 간단히 확인했습니다. 화면은 1080×2400이며 수동 제어 미지원 AE 프리뷰 경로였습니다. 시작 표시 `f/4.0`, `ISO 100`, `1/60s`에서 조리개를 스와이프로 `f/5.6`으로 바꾼 뒤 AUTO를 눌렀을 때, `f/5.6`과 `ISO 100`은 유지되고 셔터가 `1/30s`로 갱신됨을 스크린샷으로 확인했습니다. 로컬 확인 이미지는 `app/build/lightmeter-auto.png`, `app/build/lightmeter-auto-after.png`에 있으며 빌드 산출물로 취급합니다.

이 확인은 A/S 선택 추가 전 해당 에뮬레이터의 조리개 우선 화면·값 갱신 정상 경로에 한정합니다. 새 A/S UI와 S 경로, 실기기, 실패·취소 경로의 기기 실행 검증, 좁은 화면·큰 글꼴의 배치는 아직 확인하지 않았으며, 측광 정확도나 다른 기기의 동작을 보장하는 결과가 아닙니다.

A/S 우선순위 추가에서는 같은 명령으로 빌드·테스트·lint를 검증했고 JVM 테스트 28개가 통과했습니다. 양쪽 축의 계산과 경계 방향, 모드 기본값·저장 코드 복원, S의 준비 셔터 1/60s, 진행 중 우선순위 변경에 따른 취소와 늦은 결과 차단을 추가 확인했습니다. 기존 lint 경고 39건은 남아 있습니다. A/S 검증 시점에는 `emulator-5554`가 연결되어 있지 않아 새 선택 UI의 실행 확인은 하지 못했습니다.

실기기에서는 밝고 어두운 환경의 초기 선택과 범위 초과 표시, 수렴 지연·메타데이터 누락 시 fallback, 준비 중 카드 조작과 중단·복귀, 권한 거부·재허용, ISO 125 등 중간값의 재실행 복원, 미지원 기기 AE 프리뷰, 큰 잔여 보정 상태의 반복 스와이프와 Color/B/W 병행을 확인해야 합니다.

AUTO는 f/8 등 현재 조리개에서의 재측광, 완료 후 장면 변경 시 카드 고정, 연속 클릭, 측정·적용·복원 중 카드/스톱/B/W 조작, 미수렴 및 수동 적용 실패 후 이전 프리뷰 복원, 복원 도중 중단·Activity 재생성, 권한 재허용과 좁은 화면·큰 글꼴의 버튼 배치를 확인해야 합니다.

A/S에서는 선택만 바꿨을 때 카드·노출 요청 유지, S AUTO의 셔터·ISO 고정과 조리개 갱신, 저장 S의 새 실행 시 1/60s 유지, Activity 재생성의 카드·모드 복원, 초기 AE·AUTO 적용 중 모드 변경의 취소·복원, 조리개 양쪽 한계 안내 및 48dp 선택부의 작은 화면·큰 글꼴 배치를 추가 확인해야 합니다. 조작부 높이 분기는 유지했으며 새 선택부 때문에 행을 늘리지는 않았습니다.

`app/src/test/java/com/lightmeter/app/StartupExposureTest.kt`에서 초기 등가 계산, 로그 오차 선택, 범위 초과, ISO 복원, 불완전한 메타데이터, 미수렴 상태와 늦은 요청/프레임, 수동 보정 유지 및 일회성 재측광 트랜잭션을 JVM 테스트합니다. `testDebugUnitTest`로 실행합니다. 권한 허용·거부, 스와이프, 실제 물리 설정과 프리뷰, 밝고 어두운 환경의 보정, 전체화면 배치는 별도로 실기기에서 확인합니다. 빌드·JVM 테스트 성공과 실기기 검증은 구분합니다.

## 배포와 협업

- 서명된 APK는 Android Studio의 서명 APK 생성 기능 등으로 만듭니다. 현재 `app/build.gradle.kts`에는 release 서명 설정이 없으므로 `assembleRelease`만으로 배포용 서명 APK가 준비된다고 가정하지 않습니다.
- 기존 앱을 업데이트하려면 같은 서명 키를 사용하고 `versionCode`를 증가시킵니다. 배포 태그와 실제 APK의 소스·버전을 맞춥니다.
- APK는 Git에 커밋하지 않고 GitHub Release 자산으로 첨부합니다. 서명 키와 비밀번호도 저장소에 추가하지 않습니다.
- `v1.0.1`은 전체화면·컷아웃 회피 요청·조작부 높이 개선을 포함한 배포 이력입니다. 새로운 변경이 자동으로 기존 태그나 APK에 반영되지는 않습니다.
- 에이전트 작업 규칙은 [AGENTS.md](AGENTS.md)를 따릅니다. 커밋 메시지 작성·검토·실행에는 `korean-git-commit` 스킬을 사용합니다.
